# Session Protocol

## Start of session

Когда пользователь начинает новую сессию и даёт задачу, агент должен:

1. Прочитать `docs/AGENTS.md`.
2. Прочитать `docs/DOCS_INDEX.md`.
3. Прочитать `docs/HANDOFF.md`.
4. Прочитать `docs/CURRENT_TASKS.md`.
5. По задаче определить, какие дополнительные `.md` нужны.
6. Открыть только релевантные документы.
7. Кратко восстановить контекст:
   - над чем работаем;
   - что уже сделано;
   - какие активные задачи;
   - какие риски;
   - какой следующий безопасный шаг.
8. Только после этого приступать к работе.

Агент не должен читать все `docs/*.md` по умолчанию.

## During session

- Соблюдать safety rules из `docs/SAFETY_RULES.md`.
- Если задача меняет код, данные, sync или архитектуру, заранее открыть соответствующие docs через `docs/DOCS_INDEX.md`.
- Если найден баг, сразу добавить или обновить запись в `docs/BUGS_AND_INCIDENTS.md` при завершении задачи.
- Если принято решение, обновить `docs/DECISIONS.md`.
- Если контекст переполнен, восстановиться через `docs/AGENTS.md`, `docs/DOCS_INDEX.md`, `docs/HANDOFF.md`, `docs/CURRENT_TASKS.md`, затем последние записи `docs/DEV_LOG.md` при необходимости.

## End of session

Когда пользователь пишет "сессия закончена", "заверши сессию", "обнови контекст" или аналогичную команду, агент должен:

1. Обновить `docs/HANDOFF.md`.
2. Обновить `docs/CURRENT_TASKS.md`.
3. Добавить запись в `docs/DEV_LOG.md`.
4. Обновить `docs/PROJECT_STATE.md`, если изменилось состояние проекта.
5. Обновить `docs/BUGS_AND_INCIDENTS.md`, если были ошибки.
6. Обновить `docs/DECISIONS.md`, если были приняты решения.
7. Обновить `docs/OPEN_QUESTIONS.md`, если появились неясности.
8. В конце дать краткое резюме:
   - что сделано;
   - какие файлы изменены;
   - что осталось;
   - с чего начинать следующую сессию.

## Documentation update minimum

После каждой значимой задачи обновлять минимум:
- `docs/HANDOFF.md`;
- `docs/CURRENT_TASKS.md`;
- `docs/DEV_LOG.md`.

Дополнительные обновления делать по `docs/AGENTS.md` и `docs/DOCS_INDEX.md`.
